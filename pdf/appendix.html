Prompt 1 — Architecture & state model

"Design the state model for a scene editor where generation jobs run asynchronously. Constraint: reorder and trim must never restart a running generation. The user's edits (script, order, duration) and approved assets must survive a generation failure. Separate persistent scene state from job state. Use revision numbers to detect stale completions — a job that finishes after the script changed must be flagged, never auto-approved. Export eligibility should be a derived selector, not a mutable boolean."

AI response relied on

Proposed two normalized stores — scenesById (user-editable: script, mediaType, durationSec, approvedAssetId, contentRevision) and jobsBySceneId (system-managed: jobId, inputSnapshot, inputRevision, status, candidateAssetId). Reorder touches only sceneOrder. Retry snapshots the current scene state and creates a fresh job with a UUID idempotency key. On completion, if inputRevision !== contentRevision, mark as "outdated." Export gate: sceneOrder.every(id => scenesById[id].approvedAssetId !== null).
